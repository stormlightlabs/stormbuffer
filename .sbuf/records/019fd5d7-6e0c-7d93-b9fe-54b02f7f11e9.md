Markdown records with TOML frontmatter are the source of truth. SQLite, FTS, vectors, embeddings, and generated output are disposable projections and must contain nothing that cannot be rebuilt from those records.

Core writes commit the canonical record first using a store lock, temporary file, `fsync`, and atomic replacement, then update the SQLite projection. If projection work fails after the record commits, keep the Markdown and repair the projection with `stormbuffer sync`; never roll back or discard the canonical record because an index update failed.
